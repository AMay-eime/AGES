## 1. 人がAGESでゲームを作る

### 新しいゲームを始める
1. AIに企画を伝える（「〜なゲームをAGESで作りたい」）
2. AIが `ages init` でプロジェクトを作り、「一緒に決めるか、AIにおまかせか」を聞いてくる
3. 一緒に決める場合: `EDITOR-PLAN.md`（エディタ計画書）の質問に答える。どんな値を何度も調整したいか、どんな表や行列が要るか、どんな専用ウインドウがあると速いか、など。計画書を読んで、よければ「合意」にチェックを入れる（またはAIに「合意します」と伝える）
   おまかせの場合: AIが計画書を全部埋めて、要点を伝えてくる。決めた内容は計画書に「AI案」として残るので、いつでも見直して変えられる
4. ここからAIがエディタとゲームを作り始める。面白さの核・手触り・個性はあなたが決める

### AIのアプリとつなぐ（MCP）
- `ages init` で作ったプロジェクトなら、Claude Code などで開くだけでつながる（`.mcp.json`）
- それ以外は README の「MCP」の手順で足す

### 起動
```sh
node src/editor/server.ts <プロジェクトのフォルダ>      # 例: examples/shooter
# ブラウザで http://localhost:5170 を開く
```
- 右上の「名前」に自分の名前を入れる（操作ログに残る）

### 値を変える
- 階層・ゲーム画面・プロジェクトから選ぶと、インスペクタに出る
- 入力欄やスライダーで変える。変えた値には ★ が付く（AIは確認なしに変えない）
- ゲーム画面ではドラッグで位置を動かせる

### ロックする（AIに絶対に触らせない値）
- インスペクタの各値の右にある 🔓 を押すと 🔒 になる。もう一度押すと解除
- ロック中の値も、人はふつうに編集できる（ロックの値も新しい値に更新される）
- インスペクタ右上の「🔒を隠す」にチェックすると、ロックした値が表示されなくなる。決め終えた値を画面から外して、残りに集中できる（設定は人ごとにブラウザに記憶される）

### 「🔒⚠ ロックの記録を確認」が出たら
- ロックの記録が、あなたがエディタで設定した内容と一致しないときに出る（AIが記録を直接書き換えた／Gitでチームのロックを取り込んだ直後／この端末で初めて開いた）
- 押すと、消されたロック・増えたロック・値が変わったロックが一覧で出る
- 覚えのない変更なら「前の状態に戻す」、チームの変更なら「この内容で承認する」
- 確認するまでAIからの編集はすべて止まり、あなたが最後に封印したロックは効き続ける

### 行列（2次元のパラメータ）を編集する
- インスペクタでは大きさだけが表示される。「開く」で行列タブに、「↗」で別のブラウザウインドウに開く
- ↑↓・Enterで上下に移動、Tabで右へ。表計算ソフトでコピーしたセル範囲はそのまま貼り付けられる
- 変えたセルは枠で示される。「保存」で確定（変わったセルだけが記録される）
- AIはロックされた値を、どんな方法でも変えられない。ファイルを直接書き換えられても自動で元に戻る

### 遊んで確かめる
- ▶ 再生 / ⏸ 一時停止 / ⏭ 1フレーム送り / ⏹ 停止
- 再生中にインスペクタで値を変えると、その場で反映される。停止時に「保存するか」をチェックで選べる
- ● 記録して再生 で入力を `recordings/` に保存。AIに「この操作で起きるバグを直して」と頼める

### ウインドウの配置
- タブをドラッグで別の場所へ。右クリックでも移動できる
- 境界線をドラッグで大きさを変える。配置は自動で保存される
- プロジェクト独自のウインドウは AIに「〜を調整するウインドウを作って」と頼む（`editor/*.window.ts`）

### チームで作業する（Git）
- 「Git」タブでプル → 作業 → コミット → プッシュ
- コミットの説明は操作ログから自動で下書きされる
- 同じ値を2人が変えたときだけ衝突する。衝突したらテキストタブで該当のJSONを開いて選ぶ

## 2. AIがAGESでゲームを作る

[../AGENTS.md](../AGENTS.md) に従う。要点: 最初に `ages map` と `ages log`、値は `ages set/patch` で変える、🔒は変えない、★は人に確認、`ages run` で確かめる。

## 3. AGES自体を開発する

### 作業を始めるとき
1. [VISION.md](VISION.md)（理念）と [PLAN.md](PLAN.md) の「現在地」を読む
2. 関係する決定を [DECISIONS.md](DECISIONS.md) で確認する
3. `git log --oneline -10` と開いているPRを確認する

### 作業の流れ
1. main から作業用ブランチを作る（main に直接プッシュしない）
2. 実装する（§4の決まりに従う）
3. 確かめる
   ```sh
   npm test                 # テスト（必須）
   npm run check            # 型チェック（npm install 済みなら）
   node bin/ages.js run examples/shooter --frames 1800 --keys "0-1800:KeyZ" --twice   # 再現性
   ```
   エディタを変えたら、実際にブラウザで開いて動かす（コンソールエラーがないことも確認）
4. **ドキュメントを更新する（毎回）**
   - [PLAN.md](PLAN.md) の「現在地」と段階のチェック
   - 新しく決めたことは [DECISIONS.md](DECISIONS.md) に、理由と一緒に追記
   - 使い方が変わったら [../README.md](../README.md) と、AIの手順が変わったら [../AGENTS.md](../AGENTS.md)
5. コミット（説明は日本語、何をなぜ）→ プッシュ → PR
6. **取り込みは、開発者がその場で「取り込んで」と言ったときだけ AI が行う**（テストが通っていること。古い PR から順に）。言われていなければ、AI は取り込みを待たずに前の PR のブランチの上に積んで次へ進む。積んだ PR は main 向けに作り、前の PR を含むことを説明に書く（2026-11-08 → 2026-11-09 に変更。開発者の指示がある取り込みは、実行環境の安全確認を通った）

### テスト用のサンプルを汚さない
エディタやCLIで `examples/shooter` を試した後は、元に戻してからテストする:
```sh
git checkout -- examples/shooter/scenes examples/shooter/prefabs
rm -rf examples/shooter/.ages examples/shooter/recordings/*.json
```

## 4. 機能を足すときの決まり

- **理念の2指標（思考時間・トークン）を悪くしないか**を最初に考える
- **実行時の外部依存を足さない。** どうしても必要なら理由を DECISIONS.md に書く
- **TypeScriptは「消すだけで動く書き方」だけ。** enum・名前空間・コンストラクタ引数でのプロパティ宣言は使わない。import には `.ts` を付ける
- **`src/core` と `src/render` はブラウザでもNodeでも動くこと**（`node:` の機能を使わない）。Node専用は `src/project` `src/cli` `src/editor/server.ts` `worker.ts`
- **AI向けの出力は短く。** 一覧は1行1件、変化は「前→後」、長いJSONは `--dump` のときだけ
- **エラーには場所・範囲・候補を書く**（`suggest()` を使う）
- **人の編集はすべて `Project.apply` などを通して操作ログに残す。** 直接ファイルを書く処理を足すときも、ログと★・🔒の扱いを必ず考える
- **ロックは決して弱めない。** AIの経路（CLI・将来のMCP）からロックを設定・解除・回避できる機能は作らない
- **テストを足す。** 特に、ロック・★・再現性・「全部成功か何も変えないか」に関わる変更
